# QuestKeep — Техническое задание

## 1. Обзор проекта

**Название:** QuestKeep (рабочее название)  
**Платформа:** Android  
**Цель:** Мобильное приложение для автоматизации игровых процессов НРИ (табличных ролевых игр), управления персонажами и коммуникации между ГМ (Гейм-мастером) и игроками.

**Основная ценность:**
- Единый инструмент для всех участников игры
- Облегчение работы ГМа при управлении группой
- Удобное ведение персонажей для игроков
- Синхронизация в реальном времени

---

## 2. Технические требования

### 2.1 Stack & Architecture
- **Язык:** Kotlin
- **UI Framework:** Jetpack Compose (современный подход, минимум XML layouts)
- **Минимум API:** Level 28 (Android 9.0+)
- **Архитектура:** MVVM + Repository Pattern
- **Dependency Injection:** Hilt
- **Асинхронность:** Kotlin Coroutines + Flow
- **Локальная БД:** Room Database
- **Real-time синхронизация:** WebSocket (либо Firebase Realtime DB, если нужна быстрота)

### 2.2 Backend (требуется решить)
**Вариант A: Firebase** (быстрее развертывается)
- Firebase Authentication (Email/Password + Google OAuth)
- Cloud Firestore (для данных)
- Cloud Messaging (Push-уведомления)

**Вариант B: Custom Backend** (больше контроля)
- Node.js/Express или Python/Django
- PostgreSQL (основная БД)
- Socket.io для WebSocket
- JWT для аутентификации

**Рекомендация:** На MVP используй Firebase — быстрее, меньше devops-работы.

### 2.3 Design & UI
- **Основная тема:** Dark Theme (обязательна)
- **Design System:** Material Design 3
- **Responsive:** Поддержка телефонов (5"-7") и планшетов (7"+)
- **Ориентация:** Portrait (основная), Landscape (опционально для планшетов)

## 3. Архитектура ролей

Приложение имеет две роли с разными интерфейсами и правами доступа:

### 3.1 Мастер (Game Master)
- Создатель и администратор кампании
- Управляет всеми игроками в группе
- Видит скрытую информацию (заметки, статы)
- Может отправлять приватные сообщения

### 3.2 Игрок (Player)
- Может состоять в нескольких группах одновременно
- Видит только свои персонажи и групповую информацию
- Управляет своим чарлистом и ресурсами
- Участвует в групповом чате

### 3.3 Переключение ролей
- Пользователь может быть одновременно ГМом в одной кампании и Игроком в другой
- Выбор роли при регистрации (с возможностью смены позже)

## 4. Функциональные требования

### 4.1 Система авторизации и профиля

#### Регистрация
- Email + Пароль (минимум 8 символов, одна буква, одна цифра)
- OAuth через Google Account
- Выбор никнейма (3-20 символов, уникальный)
- Обязательная верификация email

#### Профиль пользователя
- Смена аватара (загрузка фото или выбор из галереи)
- Смена никнейма
- Просмотр активных персонажей и кампаний
- История игр
- Настройки уведомлений

---

### 4.2 Функции ГМа (Game Master Tools)

#### 4.2.1 Управление группами / кампаниями
- **Создание кампании:**
  - Название, описание, игровая система (D&D, Pathfinder, etc.)
  - Максимальное количество игроков (1-5)
  - Уровень доступа (приватная / по приглашению)
  
- **Управление игроками:**
  - Приглашение через пригласительный код / уникальную ссылку
  - Удаление игрока из группы
  - Выдача/отзыв ролей
  - Просмотр статистики участия

- **Синхронизация сессий:**
  - Запуск/завершение игровой сессии
  - Объявление перерыва
  - Push-уведомление игрокам о начале игры

#### 4.2.2 Мастерские заметки (Dungeon Master Notes)
- **Древовидная структура:**
  - Мир → Город/Локация → НПС/Враги → Сюжетные развороты
  - Поддержка форматирования (Bold, Italic, Lists, Code blocks)
  - Вложение изображений и ссылок

- **Приватность:**
  - Полностью скрыто от игроков
  - Возможность пометить части заметки как "раскрыто для игроков"

- **Функционал:**
  - Поиск по заметкам
  - Древовидная навигация
  - Быстрый доступ к часто используемым

#### 4.2.3 Управление персонажами игроков
- **Просмотр карточек:**
  - Полная информация о персонаже в реальном времени
  - Отслеживание изменений статов игроков
  
- **Скрытые навыки (Hidden Stats):**
  - ГМ может добавлять статы, которые игрок не видит до момента раскрытия
  - Например: "Проклятие", "Инфекция", "Трансформация в процессе"
  - Возможность раскрыть для конкретного игрока или всей группы

- **Выдача опыта (XP):**
  - Выдача индивидуально каждому игроку
  - Выдача всей группе одновременно
  - История выданного опыта

#### 4.2.4 Коммуникация
- **Приватные сообщения ("Шепот"):**
  - Отправка скрытого сообщения конкретному игроку
  - Видно только получателю и ГМу
  - Может содержать результаты скрытого броска, подсказку и т.д.

- **Push-уведомления:**
  - Оповещение о предстоящей игре (за день, за час)
  - Оповещение об получении приватного сообщения
  - Настройка тихих часов

#### 4.2.5 Бестиарий (Bestiary)
- **Создание карточек НПС и монстров:**
  - Имя, описание, характеристики (HP, броня, навыки)
  - Быстрая вставка в чат или заметки
  
- **Управление:**
  - Сохранение в библиотеку (в рамках кампании)
  - Использование в разных сессиях
  - Шаблоны для типовых врагов

---

### 4.3 Функции Игрока (Player Tools)

#### 4.3.1 Интерактивный чарлист (Character Sheet)
- **Основные поля:**
  - HP (текущее / максимум) с визуальной полоской
  - Броня и ее поглощение / AC
  - Основные характеристики (Самочувствие,Движение, Сражение, Мышление, Внимание, Общение)
  - Боевые параметры (DMG, Dodge, Initiative bonus)

- **Быстрые действия:**
  - Долгий тап по HP → окно быстрого изменения (урон/лечение)
  - Быстрые кнопки для частых действий

- **Редактирование:**
  - Игрок может редактировать свои статы (с историей изменений)
  - Некоторые поля могут быть заблокированы ГМом (прочитано только)

#### 4.3.2 Трекер ресурсов (Resource Tracker)
- **Настраиваемые счетчики:**
  - 4 Ресурса магии, как ячейки: Куар, Омбра, Веруна, Сумени (могут иметь значения 0, 0.5, 1, 1.5, 2 и т.д.)
  - Очки вдохновения максимум 6
  - Пользовательские ресурсы (создает сам ГМ)

- **Визуализация:**
  - Полоски прогресса для каждого ресурса
  - Быстрое изменение (±1, ±5, установить значение)
  - История использования ресурсов

#### 4.3.3 Древо навыков (Skill Tree / Abilities)
- **Визуальное отображение:**
  - Иерархия навыков (Основное умение → Подумение → Специализация)
  - Иконки для каждого навыка
  - Статус (активирован / доступен / заблокирован)

- **Прокачка:**
  - Возможность тапнуть на навык и прокачать (если доступно)
  - Показать требования для прокачки (нужный уровень, ресурсы и т.д.)
  - История изменения уровня навыков

- **Описание:**
  - Полное описание каждого умения (может быть с форматированием)
  - Эффекты и модификаторы

  Возможность мастеру создавать новые умения.

#### 4.3.4 Групповой чат (Group Chat)
- **Базовый функционал:**
  - История сообщений
  - Имя отправителя + аватар
  - Тип сообщения: обычное, системное (ХМ совершил действие), приватное "шепот"

- **Форматирование:**
  - Поддержка базового Markdown: **bold**, *italic*, `code`, ~~strikethrough~~
  - Ссылки и вложение изображений
  - Список упоминаний игроков (@name)

- **Кэширование:**
  - Автоматическое сохранение истории сообщений локально
  - Синхронизация при подключении
  - Поддержка оффлайн-режима (отправка при восстановлении связи)

#### 4.3.5 Мультиперсонажность
- **Несколько персонажей:**
  - Разные персонажи для разных групп
  - Быстрое переключение между персонажами
  - Синхронизация персонажей в облаке

- **Экран выбора:**
  - Список всех активных групп и персонажей
  - Иконка / аватар персонажа
  - Последнее действие / дата последней игры

#### 4.3.6 Справочник (Reference / Rules)
- **Хранилище информации:**
  - PDF-ридер для загруженных правил (или встроенная Wiki)
  - Поиск по правилам
  - Закладки для часто используемых разделов

- **Интеграция:**
  - Ссылка из чарлиста на соответствующие правила
  - Быстрый доступ из описания навыков

---

### 4.4 Общий функционал

#### 4.4.1 Глобальный Dice Roller (Броскатель костей)
- **Доступ:**
  - Floating Action Button (плавающая кнопка) в углу экрана
  - Боковая шторка / Sheet (свайп снизу)
  - Также может быть вызван из чата через команду `/roll`

- **Поддерживаемые кости:**
  - Стандартные: d4, d6, d8, d10, d12, d20, d100
  - Множественные броски: 2d6, 3d20 и т.д.
  - Кастомные: d3, d30 и т.д.

- **Функциональность:**
  - Добавление модификаторов: d20+5, d20-3
  - Сохранение "пресетов" (например, "Атака мечом: d20+5, урон: d8+3")
  - История последних бросков

- **Конфиденциальность:**
  - Публичный бросок → результат отправляется в групповой чат
  - Скрытый бросок → результат видит только игрок и ГМ
  - Бросок ГМа → может быть полностью скрыт от игроков

- **Визуализация:**
  - Анимация падения костей
  - Четкое отображение результата и суммы
  - Иконки для каждого типа кости

## 5. Дополнительные функции (Phase 2.0+)

### 5.1 Инициативная лента (Combat Tracker)
- ГМ запускает режим боя
- Игроки кидают инициативу
- На экранах всех появляется очередь ходов
- Визуальное выделение текущего персонажа
- Автоматический переход к следующему ходу

### 5.2 Инвентарь с весом (Inventory System)
- Список предметов с весом и стоимостью
- Автоматический расчет общего веса
- Проверка перегруза в зависимости от силы персонажа
- Быстрое использование предметов (зелье, свиток и т.д.)

### 5.3 Туман войны (Fog of War)
- ГМ может "открыть" часть заметки или изображение (карту) для игроков
- Выборочное раскрытие информации
- Синхронное обновление для всей группы

### 5.4 Звуковая доска (Soundboard)
- ГМ может запускать фоновую музыку или звуковые эффекты
- Синхронное воспроизведение у всех игроков
- Библиотека типовых звуков (шум дождя, боевая музыка, таверна и т.д.)

### 5.5 Оффлайн-режим (Offline Mode)
- Кэширование основных данных чарлиста
- Возможность просмотра и редактирования персонажа без интернета
- Синхронизация при восстановлении сети
- Уведомление при невозможности выполнить операцию онлайн

### 5.6 Генераторы (Generators)
- Генератор имен (по расам, культурам)
- Генератор лута (случайные предметы в сундук)
- Генератор НПС (быстрое создание второстепенного персонажа)

## 9. Известные ограничения и риски

### Техническое
- **Real-time синхронизация:** Может потребоваться оптимизация при большом количестве игроков в чате
- **Battery drain:** WebSocket + постоянная синхронизация могут быстро разрядить батарею (нужны оптимизации)
- **Сетевые ошибки:** Нужна корректная обработка потери подключения и retry-логика

### Функциональное
- **Масштабируемость:** На MVP не рассчитываем на 100+ человек в одной группе
- **Offline sync:** Конфликты при редактировании одного персонажа несколькими пользователями нужно обработать

### Безопасность
- Валидация входных данных на фронте и бэке
- Защита от injection-атак в чате (sanitize Markdown)
- Проверка прав доступа перед выдачей Hidden Stats
